# 欧盟EUDAMED强制使用后SS(C)P合规重构：MDCG新立场文件的核心变化与全生命周期管理应对

## 一、政策背景与意义

2026年10月30日，欧盟委员会医疗器械协调小组（MDCG）发布了关于EUDAMED强制使用后安全与临床性能摘要（SSCP，也称SS(C)P）管理立场文件的新修订版。该修订版针对植入式器械和III类器械制造商、公告机构以及参与SSCP提交和验证的EUDAMED用户，对SSCP在EUDAMED中的编制、上传、验证、公开和生命周期管理提出了一揽子澄清与细化要求。

从法规基础上看，SSCP制度源于《医疗器械法规》（EU）2017/745（MDR）第32条。该条明确要求植入式器械和III类器械制造商编制安全与临床性能摘要，并由公告机构进行验证，验证后由制造商提交至EUDAMED。SSCP不同于使用说明书（IFU），也不是临床评价报告（CER）的全文替代，而是面向患者、使用者和医疗专业人员的一份经过公告机构验证的公开性安全与临床性能信息摘要。其内容应涵盖器械识别信息、预期用途、适应症、禁忌症、残余风险、临床性能数据、上市后临床跟踪（PMCF）计划等关键要素。

EUDAMED作为MDR第33条项下的欧洲医疗器械数据库，其各模块自2020年起陆续开发并分阶段投入自愿或强制使用。在EUDAMED强制使用前，制造商提交SSCP往往通过其他渠道或仅在文件层面满足要求；随着EUDAMED相关模块进入强制使用阶段，SSCP的电子提交、公告机构在线验证、版本状态流转以及公开访问成为一项法定合规动作，而不再仅是文件管理问题。此次MDCG立场文件新修订版正是在这一“后强制使用”背景下发布，旨在解决实务中频繁出现的状态不清、版本混乱、权限不明、语言版本缺失、与公告机构验证流程脱节以及与上市后监督数据联动不足等痛点。

因此，本次修订版的监管意义不仅在于解释既有条款，更在于将MDR第32条、第33条以及欧盟委员会关于EUDAMED的实施条例（(EU) 2021/2078）等要求，转化为一套可落实到系统操作层面的管理规则。相关方若不及时调整内部SSCP流程，可能导致公告机构拒绝验证、EUDAMED公开信息过期、主管当局监管不符合项，甚至在极端情况下影响器械的市场准入与持续投放。

## 二、核心变化分析

本次MDCG立场文件修订版的核心变化可归纳为以下七个方面。

### 1. EUDAMED中SSCP状态模型与角色权限再界定

新修订版对SSCP在EUDAMED中的状态流转进行了明确，通常包括“草稿”（draft）、“待公告机构验证”（ready for validation）、“验证中”（validation in progress）、“已验证”（validated）、“已发布”（published）、“需更新”（update required）以及“撤回”（withdrawn）等状态。制造商作为提交责任主体，可以创建草稿、发起验证请求并在退回后重新提交；公告机构则具有验证、退回、要求补充资料以及批准发布的权限。新版本强调，一旦SSCP被公告机构验证并发布，制造商不能直接修改已发布记录，任何实质性修订都必须作为新版本重新进入验证流程。这一安排确保EUDAMED中的SSCP具备完整的审计追踪和版本控制，避免“静默修改”公开文件。

此外，立场文件重申了不同EUDAMED参与者角色的权限边界。制造商应通过EUDAMED Actor模块完成注册，并由本地的Local Actor Administrator（LAA）或等效管理员进行SSCP相关权限分配。公告机构、欧盟委员会成员国主管当局和公众的查看权限亦被区分，防止非授权主体对验证状态或未公开内容的误操作。

### 2. SSCP编写模板与数据结构更新

新修订版进一步对齐了MDCG此前发布的SSCP标准模板（如MDCG 2019-9系列），并针对EUDAMED系统特点对数据结构提出更细致要求。制造商需使用结构化字段填报器械识别信息，包括但不限于Basic UDI-DI、UDI-DI、器械商品名、风险分类、公告机构证书编号、预期用途、适应症、禁忌症、目标患者人群、使用环境和操作所需资质等。立场文件强调，Basic UDI-DI与EUDAMED UDI/器械模块中的注册数据应保持一致，否则可能导致验证失败。

此外，模板更新意味着过去基于旧版本模板编制的SSCP可能无法完全满足新系统字段映射要求。制造商应在下一次提交或更新前，对现有SSCP进行结构性差距分析，确保内容可以正确映射至EUDAMED数据字段，而非仅仅以PDF附件形式上传。

### 3. 生命周期管理触发条件与年度更新

MDR第32(6)条要求，III类器械和植入式器械的SSCP应至少每年更新一次。本次立场文件进一步澄清了年度更新的起算基准，应以公告机构首次验证通过的日期为起点，而非器械首次上市日期或CE证书颁发日期。同时，立场文件细化了除年度更新外的触发条件，包括：器械发生重大变更、临床评价更新导致风险-获益结论变化、上市后监督（PMS）或上市后临床跟踪（PMCF）评价/报告产生新的安全性或临床性能结论、现场安全纠正措施（FSCA）、公告机构证书范围变化、以及EUDAMED中器械注册数据发生重大变化等。

对于上述触发条件，制造商不应等待年度到期日，而应在触发事件完成后及时启动SSCP修订。新版立场文件特别强调，SSCP的更新必须基于经批准的最新临床评价和上市后监督数据，且更新内容应与PSUR、PMCF评价报告等文件保持一致。公告机构在验证更新版本时，会核查其与上述文件的一致性。

### 4. 公告机构验证流程与退回/整改

新修订版对公告机构的验证职责进行了流程化描述。公告机构应基于MDR第32条和相应指定文件，对SSCP的内容完整性、与临床评价报告及技术文件的一致性、是否存在与器械安全性或临床性能相关的误导性表述等作出验证。立场文件虽未创设新的法定验证时限，但明确要求公告机构建立标准操作程序（SOP），避免因流程不透明造成不必要的延误。同时，公告机构在退回SSCP时，应在EUDAMED中给出明确的退回原因代码或说明，并区分是形式性问题、内容缺陷还是与技术文件不一致。

制造商收到退回后，应根据公告机构意见进行整改，并以新版本形式重新提交。若仅涉及拼写错误或非实质性字段修正，部分情形下可依据公告机构程序以附加说明方式处理，但不应绕过版本管理规则直接修改已发布内容。立场文件还提示，公告机构的验证行为不替代制造商对SSCP内容真实性和完整性的主体责任。

### 5. 语言版本管理与公开文本的不可编辑性

根据MDR第32(5)条，SSCP应以器械拟上市成员国接受的官方语言编写。本次立场文件进一步明确，多语言版本应作为同一SSCP记录之下的关联文件进行上传，而不是在EUDAMED中建立多个独立的SSCP记录。基础验证版本通常为公告机构审阅的源语言版本；翻译版本需与源语言版本保持一致，但原则上公告机构的验证对象是源语言内容，除非相关法规或公告机构协议另有约定。制造商应确保所有语言版本在发布前完成内部审核，避免翻译错误导致公开信息不一致。

另一重要变化是，EUDAMED中已发布的SSCP文本具有不可直接编辑性。任何语言版本的勘误、修订或替换，都必须纳入整体版本控制，并保留历史版本供审计追踪。这一要求对制造商的翻译管理、版本同步和文档变更控制提出了更高要求。

### 6. SSCP与EUDAMED其他模块数据联动

EUDAMED并非孤立数据库，其Actor、UDI/器械、公告机构与证书、临床研究/性能研究、警戒和市场监管等模块存在内在数据关联。本次立场文件强调，SSCP中的器械识别信息、公告机构证书信息、UDI-DI/Basic UDI-DI等，应自动或半自动地从EUDAMED相关模块引用或校验。制造商在更新器械注册信息、证书信息或发生UDI变更时，应同步评估是否需要更新SSCP。反之，若SSCP中引用的证书或UDI数据失效，EUDAMED可能给出状态警示，影响SSCP的公开有效性。

这一联动机制意味着SSCP的合规不再是独立的文件工作，而应纳入制造商整体的EUDAMED数据治理体系。制造商应建立跨部门的数据一致性核查流程，确保注册、证书、PMS和SSCP各模块之间的数据不冲突。

### 7. 过渡期遗留器械的SSCP迁移与适用边界

对于依据MDR第120(3)条过渡期安排继续投放的遗留器械，其原本在指令框架下并无SSCP要求。本次立场文件指出，遗留器械仅在获得MDR公告机构证书后，才需要按照MDR第32条编制并上传SSCP。对于已获得MDR证书且此前已编制过SSCP但未在EUDAMED中提交的器械，制造商应在EUDAMED强制使用后按新流程完成迁移和上传。立场文件同时提醒，不得将遗留器械的旧指令符合性文件中的临床安全摘要与MDR项下SSCP混为一谈。

这一规定为处于过渡期的制造商划定了清晰边界，避免因对“遗留器械”概念理解不清而遗漏SSCP义务。

## 三、影响分析

### 对制造商

对植入式器械和III类器械制造商而言，本次修订版带来的最大影响是流程的系统化升级。制造商不仅要维护SSCP内容质量，还必须管理EUDAMED中的电子状态、版本、权限和语言关联。内部质量体系文件（如SOP、作业指导书）需要相应更新，将SSCP生命周期管理从纸质或分散式文件管理转变为EUDAMED驱动的电子流程。对于多品种、多语言、多公告机构的制造商，变更控制和数据一致性挑战将显著增加。未按新流程操作可能导致公告机构验证延迟、SSCP公开版本过期，或在监管审核中被认定为不符合项。

### 对公告机构

公告机构的验证工作将从原来的文档评审扩展至EUDAMED在线操作、状态管理和数据一致性核查。新修订版要求公告机构建立更透明的退回理由和验证记录，这有助于减少验证标准不一致问题，但也会增加公告机构的内部流程负担。公告机构需要培训专职人员，熟悉EUDAMED的SSCP模块操作，并与制造商在验证前进行充分沟通。若公告机构验证标准过于严格或解读不一，可能导致行业合规成本进一步上升。

### 对患者与使用者

从患者和医疗专业人员角度看，EUDAMED强制使用后SSCP公开可访问性和版本管理规范化具有积极意义。患者可在欧盟官方数据库中找到经公告机构验证的最新安全与临床性能信息，减少因信息不对称带来的风险。多语言关联管理若能切实执行，也将改善非英语国家患者的信息可及性。然而，如果语言版本更新滞后或内容过于技术化，SSCP的实际可读性和患者友好度仍可能有限。行业应继续关注SSCP的“可读性”与“公众沟通”功能，而不仅是满足法规字段要求。

## 四、合规建议

为应对本次MDCG立场文件修订版，相关方应采取以下具体行动：

1. **开展SSCP现状差距分析。** 制造商应逐条对照新立场文件，审查现有SSCP的编写模板、状态管理、版本记录、语言版本和EUDAMED提交流程，识别与修订版要求之间的差距，形成整改清单并逐项关闭。

2. **更新质量体系文件。** 将SSCP管理的SOP和作业指导书升级为覆盖EUDAMED系统操作、角色权限、状态流转、版本控制、年度更新触发、语言版本关联等全生命周期的书面程序。确保研发、临床、注册、质量、翻译和EUDAMED管理员等各职能职责清晰。

3. **完成EUDAMED角色与权限配置。** 确认Actor模块注册信息有效，LAA合理分配SSCP创建、提交、查看和审批权限。避免因权限配置错误导致公告机构无法访问或制造商无法重新提交。

4. **采用最新SSCP模板并进行结构化准备。** 在编写或更新SSCP时，使用最新模板，并确保Basic UDI-DI、UDI-DI、证书编号、EMDN/器械分类等关键字段与EUDAMED其他模块一致。建议在正式提交前进行内部字段映射测试。

5. **与公告机构建立前置沟通机制。** 在提交前与负责验证的公告机构确认其SSCP验证标准、退回原因代码、格式要求和预期时限。对于多公告机构或多证书情况，应明确各公告机构的操作差异，并在质量体系中予以规定。

6. **建立SSCP年度更新日历和触发事件监控。** 将SSCP年度更新日期与PSUR周期、PMCF评价报告、CER更新、重大变更和FSCA等关键节点关联，设置自动化提醒，确保触发事件发生后能在合理时间内启动SSCP修订。

7. **强化多语言版本管理。** 建立翻译管控流程，确保源语言版本经公告机构验证后，翻译版本经过独立审核并保持内容一致。避免因翻译错误或版本不同步影响公开SSCP的准确性和监管合规性。

8. **保存完整的电子提交和验证记录。** 虽然EUDAMED系统本身保留审计追踪，制造商仍应在内部保存提交时间、公告机构验证意见、退回理由、整改措施和最终发布版本的记录，以备主管当局审核。

9. **定期开展EUDAMED数据一致性核查。** 当器械注册信息、UDI、公告机构证书、PMS或警戒信息发生变化时，启动SSCP一致性检查，确保EUDAMED中SSCP与其他模块的数据不矛盾。

10. **开展内部培训与演练。** 对涉及SSCP编制、审核、翻译和EUDAMED操作的人员进行新流程培训，并通过模拟提交、退回和重新提交演练，降低正式操作时的错误率。

## 五、时间线与关键日期

本次MDCG立场文件修订版于2026年10月30日发布。MDCG立场文件作为欧盟层面的指导性文件，本身不直接设定法定过渡期，但其反映的是对MDR第32条、第33条和EUDAMED实施条例如何在强制使用后执行的统一监管期望。相关方应尽快着手流程调整，最好在下一个SSCP提交或更新节点前完成差距分析和质量体系更新。

对于已获得MDR证书且已有SSCP的植入式和III类器械，应在EUDAMED强制使用后的首次年度更新或触发事件更新时，全面适用新版流程。对于尚未获得MDR证书但正在申请或保持过渡期资格的制造商，应提前规划EUDAMED Actor注册、模板准备和公告机构验证流程，以确保证书颁发后能及时上传SSCP。遗留器械持有者应重点核查其器械是否已切换至MDR证书，避免遗漏SSCP义务。

建议企业法规事务部门持续跟踪MDCG后续问答、EUDAMED系统发布说明以及主管当局在本国的执法实践，因为围绕SSCP的具体操作细节仍可能通过后续文件进一步澄清。EUDAMED强制使用时代，SSCP已从静态文档转变为动态电子记录，企业唯有将SSCP纳入全生命周期数据治理体系中，才能稳健应对监管变化并保障患者安全。
